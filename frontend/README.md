# Frontend — клиентская часть сервиса управления файлами

Одностран��чное приложение для загрузки, просмотра и управления файлами с асинхронной обработкой на бэкенде.

## Стек

- **Next.js (App Router)** – React-фреймворк с маршрутизацией на основе файлов
- **TypeScript** – строгая типизация
- **React** – компонентный подход
- **Bootstrap / React-Bootstrap** – адаптивный UI
- **Layered Architecture** – чёткое разделение ответственности

## Структура проекта (src/)

```
src/
├── types/           # TypeScript-интерфейсы (FileItem, AlertItem)
│   └── index.ts
├── api/             # Сервисный слой для работы с бэкендом
│   ├── config.ts    # базовая конфигурация fetch
│   ├── files.ts     # методы для работы с файлами
│   └── alerts.ts    # методы для работы с алерами
├── hooks/           # Кастомные React-хуки для изоляции логики и состояния
│   ├── useFiles.ts  # управление списком файлов и загрузкой
│   └── useAlerts.ts # управление списком алертов
├── components/      # Переиспользуемые UI-компоненты
│   ├── FileList.tsx
│   ├── AlertList.tsx
│   └── UploadModal.tsx
└── app/             # Страницы и Layout (App Router)
    ├── layout.tsx
    └── page.tsx     # композиция компонентов и вызов хуков
```

## Переменные окружения

Создайте файл `.env.local` в корне `frontend/`:

```env
NEXT_PUBLIC_API_BASE=http://localhost:8000
```

По умолчанию используется `http://localhost:8000`. При необходимости укажите другой адрес бэкенда.

## Запуск

### Локальная разработка

```bash
npm install
npm run dev
```

Приложение будет доступно по адресу [http://localhost:3000](http://localhost:3000).

### Сборка для production

```bash
npm run build
```

### Запуск в Docker

Сборка образа с передачей адреса бэкенда через build-arg:

```bash
docker build -t frontend \
  --build-arg NEXT_PUBLIC_API_BASE=http://localhost:8000 \
  -f Dockerfile .
```

Запуск контейнера:

```bash
docker run -p 3000:3000 frontend
```

В `docker-compose.dev.yml` уже настроена передача `NEXT_PUBLIC_API_BASE` через `args`. Для продакшена используйте переменную окружения при запуске контейнера или передавайте её на этапе сборки.

## Особенности архитектуры

- **API-слой** полностью изолирует HTTP-запросы, используя `fetch` с единой конфигурацией.
- **Хуки** управляют состоянием и побочными эффектами, предоставляя чистый интерфейс для компонентов.
- **UI-компоненты** не содержат бизнес-логики и получают данные через пропсы.
- **Страницы** (App Router) только собирают компоненты и вызывают хуки, что упрощает тестирование и поддержку.

## Связь с бэкендом

Все запросы направляются на API-эндпоинты FastAPI, описанные в корневом `README.md`. Документация доступна по адресу `/docs` запущенного бэкенда.
